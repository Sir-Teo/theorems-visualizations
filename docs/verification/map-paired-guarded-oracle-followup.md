## Original owner reset

`freshAtlas(scene)` checks readiness, actual existing atlas/scratch entries and their exact original dimensions/bytes, then checks post-release headroom **before destroying anything**. A rejected preflight leaves the old atlas alive. It releases the old atlas and connected scratch before invoking the same constructor with the same GL, SceneBudget, width and height. Thus old/new atlas owners never coexist. It asserts every other actual budget entry object is identical, total/peak accounting unchanged, original model/group entries and release status unchanged, path references/control key unchanged, connected offscreen scratch style identical and replacement texture/scratch identities genuinely new. A constructor failure leaves no usable old atlas and stops the page; it must not continue a frame using the destroyed owner. The source constructor receives no map/geometry/control object and is unchanged apart from the already accepted gutter route and observation subclass.

The existing original reserve/eviction mechanism is not patched. The reset preflight ensures both replacement allocations fit synchronously without choosing an original evictable prewarm victim; all three original prewarm models remain required at the full epoch readiness and per-frame gates. The original chunk priority accounting remains untouched. No model metadata is regenerated and no geometry/worker/group/control state is reset to manufacture a passing history.

## Observation and bounded readback

The observer is installed before the first original atlas constructor. It records the actual null texture initialization's GPU RGBA hash, constructor dimensions, every clear/cursor generation, every full ordered request key/style/DPR and hit decision, returned word UV/bearing/size/generation, and every actual guarded upload rectangle with its **post-upload GPU RGBA SHA-256**. No Canvas getImageData observer is used. A request beginning, its possible clear/upload and its returned slot retain their actual order. Scene draw begin/end events are recorded from initialization onward, including unsuccessful draws. There is no asynchronous digest inside a draw.

`readRGBAChunks` attaches the existing texture to a temporary **READ_FRAMEBUFFER only**; no texture or persistent attachment is added. It saves/restores separate READ/DRAW framebuffer bindings, the prior read buffer, PIXEL_PACK_BUFFER and all WebGL2 PACK alignment/row/skip values in `finally`, with a state equality check. It does not mutate texture/active-unit, array/VAO or program bindings, and checks those too. The temporary attachment is detached and its framebuffer deleted before return/throw. One GPU read scratch is at most 1,048,576 bytes. SHA-256 uses a 64-byte block, 256-byte schedule and 32-byte state; no full atlas CPU copy is retained. A bounded trace allows at most 100,000 events / 16,000,000 serialized characters and stops on excess rather than dropping events. These diagnostic CPU objects and transient read FBO are excluded from the renderer's historical logical accounting and explicitly disclosed. Error queues cannot be restored: the observer does not call getError; explicit test/frame error checks stop on a nonzero error and do not claim arbitrary error-queue preservation.
