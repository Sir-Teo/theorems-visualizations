# Proposed paired-history full-map protocol

This is a read-only next-stage plan after the private tiny atlas candidate `bc5e18f` → `781d336`. It does not accept that candidate, run a full-map test, repair the rejected chunked-index boundary `acf697e`, or authorize timing. Independent tiny peer must pass first. The original failed matrix and its missing original readbacks remain preserved.

## First full-map question: guarded original history

Freeze the same checkpoint5 input, original graph routing and complete original scene/edge sources used by the original-only control. Route only the independently reviewed transparent-gutter transformation. Reconstruct the original unselected → selected → fractional-pan history at the exact failed viewport, DPR, theme and map transform. Capture corresponding first and later draw ordinals, including the original four-draw sequence, without intervening font events, animation, timers, Canvas fallback, screenshots or extra scene draws. Persist every complete RGBA buffer before checking a comparison. Record atlas generations, cache keys, allocation positions and upload sequence, plus model/control/group/resources and actual source/data hashes.

Compare guarded cold/warm ordinals and localize every changed pixel if any remain. The tiny intervention may explain the earlier underline-like marks; it has not established full-map stability. A remaining discrepancy stops this stage. Do not assume that a later redraw is a valid replacement for the first frame. Preserve an original unguarded control with the same explicit history. Differences between unguarded dirty output and guarded output are diagnostic evidence, not alternate-binding fidelity failures or permission to relax a threshold.

## Second question: independent paired binding oracle

Only after the first stage passes, build a separate explicit harness that routes the same reviewed gutter fix symmetrically into the complete original and private chunk variants. Each variant receives its own fresh context/page and the same frozen fonts, inputs, controls and history. Keep one test context active at a time; retain reference bytes on disk rather than a second live full-map GPU owner. The initial atlas must be genuinely fresh, not merely `clear()` on an old texture. Initialization must use the original constructor/owner dimensions; any diagnostic atlas reset must be explicit, symmetric, outside the captured history and shown not to evict original owners or change a renderer input. Never warm until a passing image appears.

Before comparing corresponding output ordinals, verify matched observable text history: complete ordered glyph request keys, native raster parameters, cache hits/misses, slot/inner UV dimensions, clear/wrap generations and actual upload rectangles/content hashes. The wider guarded upload is identical in both variants. A differing text history is a harness failure requiring investigation; it cannot silently become an accepted rendering difference. Record equivalent model geometry, controls, group order/coverage and scene dimensions, with identity comparisons interpreted within each page rather than comparing object IDs across contexts.

For each case compare original ordinal 0 against chunk ordinal 0, original ordinal 1 against chunk ordinal 1, and so forth. The two variants must be independently initialized; alternating original and chunk bindings in one mutable atlas is not this oracle. Capture full compared RGBA buffers plus lossless difference and display images before any assertion or browser closure. Use bounded transport at most 1 MiB per request with checked offsets, byte sizes and SHA256; a transport failure is a tooling failure and stops the run. Preserve every completed case and the first failed case. No threshold relaxation, cropped acceptance, or later redraw substitution.

The existing complete direct-Canvas bound remains an additional gate for each corresponding state, with its separate reference clearly named. Its screenshot or a third redraw cannot stand in for the exact GPU reference. Diagnostic RGBA arrays, encoders and disk files are outside the historical logical owner cap; state their sizes and lifetime and make no physical-process-memory claim.

## Expansion and lifecycle

Begin with the exact formerly failing state and its explicit preceding history. After a passing independent paired oracle review, expand to all original viewport/DPR/theme/selection/pan/zoom/tier states in their documented order, retaining both cold and warm comparisons. Then run the still-unrun context loss, model/control invalidation, prewarm reserve pressure, chunk-tail and partial-failure cases. The original no-eviction preflight, complete-snapshot fallback/restart rules, one MAX mask and one composite per style/tile, 64,000,000 logical bytes and 8,000,000 mask pixels stay in force. A stable atlas does not certify those independent chunk requirements.

Each stage has an immutable producer boundary and independent peer before the next expansion. Root authorizes the concrete next run after reviewing those results. Full-map 60fps stays open; no benchmark runs until correctness/lifecycle/resource gates pass and all competing heavy jobs have stopped for an explicit quiet window. Production/shared runtime remains unchanged throughout this plan.
