## Validity, interpretation and stopping

Use separate fresh browser processes, one active at a time, original first, same launch arguments/device/visibility and fixed preparation history. Record run order, actual Chrome/GPU/Metal identity, page visibility and host power/load/memory snapshots before/after each window. Obtain six fresh quiet acknowledgements plus root's quiet hold; unrelated host activity remains undisturbed and documented. No concurrent tests/builds/data writes. Order/thermal/GC effects and the small sample prevent statistical certainty; a promising result needs a separately authorized reverse-order confirmation before expansion, not a matrix immediately.

Before/after each window verify the exact state, genuine selected-statement availability, ready scene, no pending worker/font activity, three unreleased original owned models, one-pixel input canvas, zero GL errors, original history equality, logical component/ledger sums, retained/peak ≤64M and mask ≤8M pixels. Keep reserve histories from initialization. Read only minimal counter/state scalars per sample. Put scalar snapshot/validation work outside each `_draw` timer, using the identical sampler in both variants. It still runs between requested frames and therefore contributes to the measured RAF cadence; do not subtract it or describe cadence as sampler-free. Full diagnostic snapshots/GL queries go outside the timed window. Require clean **per-sample** curve optimized-tile/chunk/index deltas, zero original binds/replay/stale abort/drop, and positive real submissions; the validated-state counts reported by root (125 tiles/152 chunks/1,741,699 indices) are a useful exact-state cross-check after the saved-run peer confirms them. Initialization counters and an all-fallback pass cannot qualify.

Record (1) `_draw` wall duration, including observers and any synchronous GL waits; (2) after-callback RAF cadence, `1000×24/sum(intervals)`; and (3) drains/total elapsed separately. Neither is isolated GPU elapsed or actual displayed/composited frame timing. No GPU timer-query claim, timestamp subtraction from old artifacts, inferred GPU speedup or attribution is justified. The original is the paired persistent original scene, **not** the production Canvas renderer.

Stop before any wider state if correctness/readiness/resource/callback/path validity fails, the candidate's unrounded mean RAF cadence is below 60, or observed cadence/CPU p95 regresses against the reference. Save every interval and failure; do not trim samples, round into a pass, tune thresholds or rerun unchanged automatically. With only 24 samples and heavy observers, call a noise-dominated difference inconclusive. A failure ends this instrumented screen, not a proof that uninstrumented production cannot reach 60. Even a pass is only permission to review the next bounded measurement, and closes neither moving zoom, the wider matrix, MapView/Worker/S2 lifecycle nor the production 60 FPS gate.
