# Original studio assets and release proposal

2026-10-22. Local drafts P07/P08, revision 0.1.0. No repository-wide licence was found in the inspected checkout; the KaTeX vendor licence applies to its own vendor files and is not an atlas licence.

The original weave schematics and event diagrams are authored SVG output from `explorations/studio-views.mjs`. They are Codex-assisted illustrations of explicit models, not photographs, recordings or evidence of a performed physical task. No ARTEX image or Carnegie Hall repertoire, score, worksheet, recording or sample is imported.

The phrase is an original authored event arrangement for an eight-beat metric span. Its zero-based onset offsets are 0, 1, 1.5, 2.5, 3, 4, 5.5, 6 and 7. Two generated sine-tone versions use 0.12- and 0.42-beat gates at selectable 60/90/120 BPM, 440 Hz, peak gain 0.18, 5 ms attack and 15 ms release. `performance-model.mjs` generates mono PCM and encodes a local WAV on request. No human composer/performance, exclusive copyright status or third-party sample licence is asserted. Every WAV export embeds ASCII-escaped JSON in a NUL-terminated RIFF LIST/INFO/ICMT comment: record identity/revision, renderer version and formula, all event values, region frame bounds, synthesis settings and pending terms. Playback volume, cursor and private notes are excluded. Keep the embedded provenance with the file; editors and format conversions may strip metadata.

**Proposed public-release terms:** CC BY 4.0 for these original educational phrases/diagrams where rights apply, with attribution to the atlas project and a note that they were created with AI assistance. This is a concrete proposal, not a licence grant, rights-holder signature or decision about the entire repository. Local drafting and review proceed under the user's instruction. Record the owner's actual release decision and scope before publication; do not relabel a pending decision as clearance.

Future real sample photographs need creator/participant permissions and asset-specific terms. Future human recordings need the performance/recording contributors and permissions actually involved. Neither the schematic code nor generated PCM supplies those missing rights or observations.

Technical references inspected for playback behavior: [MDN play()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/play) (asynchronous success/rejection and blocked playback) and [MDN currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime) (seeking and time precision). The implementation derives displayed position from the native media clock and creates region-specific PCM, so stopping a four-beat region does not depend on a delayed visual timer. It does not change playback rate, which could change pitch or invoke browser time-stretching.

Format reference: [Microsoft RIFF services](https://learn.microsoft.com/en-us/windows/win32/multimedia/resource-interchange-file-format-services) and the original [IBM/Microsoft Multimedia Programming Interface and Data Specifications 1.0, INFO List Chunk](https://www.mmsp.ece.mcgill.ca/Documents/AudioFormats/WAVE/Docs/riffmci.pdf). The engineering tests independently parse the emitted chunk sizes, padding, NUL terminator and JSON round trip, and native browser playback accepts the resulting file.
