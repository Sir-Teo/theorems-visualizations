# Explicit note copy and recovery

October 22, 2026. A U3 local delivery implementation after the [retained editions checkpoint](exploration-editions.md). It adds `explore/notebooks/` to candidates that contain retained editions, including withdrawal-only candidates. The page is always noindex and never a canonical lesson. It adds no lesson or release approval.

## Reader workflow

Choose a saved or imported source, select an available edition of the same exploration, edit the proposed notes and preview the destination. Download a recovery file and confirm that it was saved and other lesson tabs were closed before copying. The source remains untouched. Only notes are copied: the destination retains its existing selections and extra saved fields; an empty destination uses that edition’s own defaults. Imported or earlier-edition selections are never interpreted as current selections. The 1,500-character limit matches the retained reader; excessive drafts are rejected without truncation.

The manager reads `atlas.exploration.v1.<id>.<revision>` stores on its origin. Import accepts the existing single-edition export, earlier-edition export and the manager’s version-1 recovery export. Unreadable raw bytes remain exportable. Imports never write saved data. Notes can be manually transferred between origins by file; there is no account synchronization, fetch, beacon or upload in the notebook modules. Private text uses DOM text/value properties, never HTML or URLs.

Withdrawn or unknown source editions can be inspected/exported from browser storage or files without loading their former content. Only live editions in the built candidate may receive a copy. Withdrawal metadata contains identity, revision and status only, with no title, activity or defaults. No notebook page is emitted for an empty real release ledger. The generic assets are included in the legacy companion, like other copied assets; they contain no lesson data.

## Persistence and limitations

A preview holds exact source and destination strings. The copy rechecks both, writes and verifies an immutable `atlas.notebook.recovery.v1.<UUID>` record containing source/before/after, rechecks the destination, writes it and reads it back. Failure leaves recovery evidence intact. A blocked/quota-failing journal prevents the destination write. An interrupted copy can be classified from exact current/before/after equality; equality is not proof of which events occurred. Undo restores the exact previous destination or its absence only when the current destination exactly equals the saved after-value. A later different edit refuses undo. Journals are never automatically deleted, including after undo.

Manager copy/undo operations use the same origin-scoped Web Lock and require secure random identities. On a browser without these APIs, or blocked storage, supported inspection/import/export stays available and writes are disabled. The old frozen lesson runtime does not use this lock. The [HTML storage standard](https://html.spec.whatwg.org/multipage/webstorage.html#introduction-16) explicitly advises assuming no locking between agent clusters; [Web Locks documentation](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) describes cooperation among callers using the same lock. Therefore these checks are **best-effort conflict detection, not an atomic compare-and-swap against old lesson tabs**. Closing those tabs and keeping the downloaded backup remain necessary. Identical-value changes (ABA), browser crashes during restoration, cleared site data, device loss and malicious same-origin scripts cannot be ruled out by value comparison. No server recovery is promised.

Files are limited to 1 MiB, 100 entries and 200,000 UTF-16 code units per raw saved entry, with bounded JSON nesting/complexity and forbidden prototype-sensitive properties. Wrong versions, IDs, revisions, arrays in place of state objects and malformed destination stores fail closed. A source’s oversized or unsupported raw string can still be downloaded in an `atlas-raw-recovery` JSON envelope for separate inspection; it cannot be copied here or admitted through the structured importer. JSON escaping preserves the complete UTF-16 string, including lone surrogate code units that a plain-text Blob would replace. The UI’s raw-data preview is explicitly bounded; export never applies that display limit.

The journal is private browser data, not an editorial receipt. Recovery files contain private notes and should be handled accordingly. The checkbox records an immediate reader decision, not a verified human study or proof that a download reached durable storage. Native tests use disposable browser contexts; no user notebook is modified by validation.

## Delivery and integration

The original six prototype records, renderer/runtime, four frozen edition bundles, runtime snapshot and review receipts remain unchanged. Only the independent edition adapter gains links, a generic notebook page and complete delivery dependency bindings. A future release approval must bind the new renderer, CSS, browser model/view and copied inventory. Earlier approvals cannot silently authorize different code.

The [integration delta](../integration/exploration-notebooks.md) replays the historical edition package from its exact Git object, then applies one preimage-checked adapter replacement and explicit additions. This preserves the earlier evidence as historical evidence and prevents an updated adapter from being mistaken for the old 19-file package. [Verification](../verification/universal-notebooks.md) records actual checks; [independent AI review](../verification/universal-notebooks-ai-code.md) has its own scope. Real release decisions, deployment, browser/assistive-technology sessions and broader master-plan work remain separate.
